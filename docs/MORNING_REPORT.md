# Утренний отчёт · Genchi Croll

На ветке `work` находится игровой сектор с фиксированным городом, четырьмя слоями и четырьмя точками переноса. В браузере проверены подбор на ходу, выстрел, дозарядка, прыжок, пауза, перенос тела и финиш. Для проверки маршрутов с отключённым таймером использован сид 740. При ускорении проверки четырёх полных маршрутов пропускалась отрисовка промежуточных кадров. Скриншоты и замер рендера сделаны отдельно с включённым WebGL.

## Проверки и производительность

- Девять проверок генератора прошли на каждом из 1000 сидов. Физический бот прошёл 400 полных маршрутов и 17 688 отдельных переходов с проверкой обеих сторон.
- Сборку из `dist/` обслуживал обычный статический HTTP-сервер по вложенному пути `/genchi-croll/`. Браузер загрузил основной модуль, текстурную оболочку из worker и все фототочки. При проверке четырёх финишей и обычного управления список ошибок консоли и страницы остался пустым.
- Сид 740, уличный автопроход, внутренние 480×270, окно 960×540, Chromium с программным рендерером SwiftShader. За 120 кадров средняя частота составила **25,8 кадра/с**. В кадре было **71–97 вызовов**, **22 948–27 018 треугольников**.
- Подготовка физики и объектов сегмента на основном потоке заняла **0,2–1,7 мс**. Сборка оболочки в worker достигала **31,1 мс**. Окно в пять сегментов вперёд даёт ей запас времени. Критерий 4 мс для полной сборки ещё открыт.
- Перенос от зарегистрированной деактивации до состояния управления занял **3,92 с**. На сиде 740 все четыре браузерных прогона завершились у ворот с четырьмя активными ретрансляторами.

## Как пробежать

После `npm ci` и `npm run dev` открыть адрес из терминала. Добавить `?seed=740`, нажать «Играть» и пройти мимо рабочего стола. Скорость спринта 8 м/с. Новая кампания меняет город.

1. **Улица.** Держаться мокрого асфальта, обходить зелёные баки и при необходимости перепрыгивать через препятствия. Бежать через зелёную площадку до ворот.
2. **Крыши.** На бирюзовом подъёме уйти влево, на разрывах прыгать с разбега. На площадке ретранслятора спуститься вместе с крышей, затем выбрать следующий подъём. Для проверки сразу на высоте открыть `?seed=740&at=seg5&layer=R`.
3. **Интерьер.** Подняться к тёплому проёму на противоположной стороне улицы. Двери открываются при приближении. Пройти по плитке до очередной площадки. Для быстрого старта использовать `?seed=740&at=seg5&layer=I`.
4. **Канализация.** Войти в шахту с бирюзовой рамкой или воспользоваться спуском из интерьера. Под землёй следовать по тоннелю до подъёма. Прямая точка проверки — `?seed=740&at=seg5&layer=U`.

Именованные точки — `?at=start|alley|fork|upper|shortcut|block|yard`. Для просмотра плана добавить `gen=debug`, для проверки сохранения ретранслятора играть без телепорта. Все команды запуска и тестов есть в README.

## Что проверить человеку

1. С какой попытки впервые удалось пройти сектор без отладочных параметров?
2. На какой развилке пришлось остановиться, чтобы разглядеть переход?
3. Какой слой проигрывает по реальной цене, с учётом врагов и ошибок?
4. Различимы ли телеграф и направление обстрела за дождём и глитчем?
5. Как меняется частота кадров на целевом i3 при первом проходе через ретранслятор?

Следующий плейтест стоит начать с сида 740 и записать время до каждого ретранслятора, выбранный слой и причину деактивации. Это позволит отличить проблемы навигации от завышенной цены боя. Полные результаты и каталог находятся в [отчёте генератора](GEN_REPORT.md).
